# 论文 claim 碎片化：实测诊断与修复方向（2026-09-27）

用户判断：“很多 claim 应该是多个论文都提出来过的，但我们之前抽取 claim 的时候，创建了太多看着不一样实则一样的节点，导致99%以上的 claim 只对应一篇论文。”以下为该判断的实测验证、根因定位与修复设计。本文件只做诊断与设计，未启动新运行，未修改固定层或生产图。

## 1. 实测：问题被证实，且比描述更极端

对冻结的 `neurooracle/data/full_v2/extracted_claims.jsonl`（905,274 条，sha256 `641d07ba…`）做只读流式统计：

| 归并口径 | 不同命题 | ≥2 篇论文 | 单篇论文 |
|---|---|---|---|
| 原文三元组（subject, predicate, object, negated） | 889,941 | 2,348（**0.26%**） | 887,593（99.74%） |
| 再加 population/atlas/direction/method | 896,635 | 800（0.09%） | 895,835（99.91%） |

即 **99.74% 的 claim 只对应一篇论文**，与用户判断一致；加上范围字段后更严重。

## 2. 排除“便宜修法”：表面规范化救不回来

按大小写、标点、连字符、空格、括号、复数、常见缩写表规范化端点后再统计：0.110% → **0.124%**。即使只在 38,169 条“干净子集”（端点 ≤3 词、无动词、无括号）上统计，也只有 0.698%。结论：**这不是清洗能解决的问题**，必须承认需要真正重建命题层。

端点的既有资产也不构成杠杆：约 64.8% 的端点串能匹配既有 `ATOMIC_MENTIONS` 原子身份，但用它替换端点键后，多论文比例 0.110% → 0.174%。端点身份不是主要瓶颈。

## 3. 根因：四类机械缺陷

1. **端点槽位没有原子化（最主要）**。`subject_name` 里 15.39%、`object_name` 里 **49.51%** 是整句式文本。实测最长 object 槽 2,170 字符（一段患者叙事），最长 subject 槽 482 字符（论文标题）。这些句子带着论文自己的措辞，因此**永远无法与另一篇论文匹配**。
2. **命题身份 = 论文措辞**。旧键用原句/原词构造，等于把论文的表述当成命题的身份。
3. **占位符污染**。`reported study outcome` 这类空槽出现 571 次，会吸走真实命题；6,929 条 subject/object 完全为空。
4. **每句话一条 claim**。每篇论文平均仅 2.34 条 claim、最多 14,304 条；13 条（含空 pmid）的“单篇最大产出者”产出数千条。粒度是句子，不是发现。

对照：全库只有 43 个谓词，其中 27 个不在受控表内（如 `binds_to`、`gene_associated_with_disease`），同句内仅 637 组因谓词同义而重复。

## 4. 修复设计：三层分离 + 稳定命题身份

已落地第一层（代码 + 11 项测试通过）：

`neurooracle/src/shared_proposition_registry.py` —— 共享命题注册表

- **命题身份只含** `subject / relation / object / polarity / qualifiers`，由构造保证**排除**论文 ID、标题、作者、年份、期刊、样本量、效应量、p 值、置信度、原句（`FORBIDDEN_KEY_FIELDS` 强制校验）。
- 因此“海马体积下降”由多篇论文写成的不同句子会落到**同一个 key**；但 population/species/脑区/模态/剂量/时点等范围差异会**拆成不同 key**，不抹平。
- 谓词走受控词表 + 同义族（`correlates_with` 与 `is_associated_with` → `association`）；未受控谓词**保留但不猜**。
- 每次 reuse/create/related/unresolved 都写**可撤销决策日志**，合并可 `merge`/`split` 回滚，证据按 work **只计一次**。
- 检索（`candidates`/`recall_keys`）只**提候选**，不做等价判定；判定仍需源绑定理由。

仍需建设的第二、三层：

**第二层：重抽取时的槽位原子化（必须）**
- 端点必须解析为**既有概念/原子引用**，禁止长句进入端点槽；无法原子化 → `unresolved` 或论文层本地概念，不得当命题身份。
- 禁止把论文标题/背景句/推荐列表句当作 subject。
- 每个（测量 × 对象 × 条件）输出一条命题，而非每句一条。
- 预期规模：现为 905,274 条 / ~387,000 篇（2.34 条/篇），偏低；按“每篇每结果 5–20 条命题”计，同语料合理规模约 **200–800 万条命题**，其中相当比例应落在多论文命题上（约 8.7 倍放大）。

**第三层：全局注册表 + 分方向证据**
- 跨批次复用同一注册表；同一命题下并列 supports / opposes / partial / unresolved，保留各自范围、数值、原句与作品身份。
- 版本/预印本去重与队列独立性分开记录，独立队列未知仍为未知。

## 8. 速度/质量试点（2026-09-27）

> 后续纠正与扩大试验见 `KG_PILOT_EXPANDED_COMPARISON_20260927.md`。以下历史段落的“命题/篇”是候选观察口径；论文数乘平均每篇观察数不能得到去重后的共享命题数。“2–6% 上界”仅为字符串召回实验结果，不是语义上界；结构通过不等于科学准确。最新 200 篇试验不支持无人自动合并；主题切片指标已获用户同意用于小规模实验。

|---|---|---|---|

### 8.1 结论一：命题数不一定上升

命题数 = 论文数 × 每篇命题数，两侧都可能下降。旧库中位数论文只有 1 条 claim（60.3% 的论文仅 1 条），属**欠抽取**；但高产出论文现有 20–28 条里大量是句子碎片与占位符，重抽取会**合并或丢弃**。本次试点每篇 7.4–8.7 条命题，比旧均值 2.30 高，但这来自更细的发现粒度，而非保留碎片。**承诺多论文比例与命题质量上升，不承诺命题数上升**；若要总量上升需显式提高每篇结果抽取密度。

### 8.2 结论二：端点原子化必要但不充分

端点已降至平均 2.3–2.6 词（旧库 object 49.5% 是整句、最长 2,170 字符），但**精确键多论文率仍为 0%**，与旧库 0.26% 同属一个失效模式：命题身份仍是论文措辞。阈值扫描显示，即使把端点相似度放宽到 0.5，跨论文可合并上界也只有 2–6%。端点**确实在跨论文重复**（`hippocampal volume` 出现在 19 篇；共享主语覆盖 13.3% 命题），但**整条命题不重复**。因此仍需要"候选召回 + 源绑定语义裁决"层，且 40 篇独立论文多为异题研究，不宜作为多论文率的分母。

### 8.3 结论三：引用失败全部是输入保真缺陷

25/25 的引用失配在**解码 HTML 实体并归一 Unicode 空白**后变成精确匹配（`&#x2009;`、`\xa0` 等）。模型引用是忠实的。另有两类**校验器表示局限**（英文单词数字 `Thirty`、千位分隔 `479 723`、区间 p 值 `P = .0007-.02`）被误记为模型错误，已在 `neurooracle/src/pilot_validation.py` 单独归为 `validator_limitations`；每例仍要求字面源绑定引用。
