## 2. 已确认的问题

### 2.1 样本不等于连贯研究队列

`freeze_cohort_v3_20260927.py` 用全文子串 `term in lowered` 判断主题。TLE 主题包含裸 `tle`，误命中 **little、subtle、startle、mantle、shuttlebox** 等词。

- 原 TLE 40篇中，**16篇没有完整TLE token或 epilepsy/epileptic**，靠这些子串进入主题。
- 例如 PMID:29785582 是 HIV 静息态连接，PMID:19435749 是多发性硬化，PMID:37798131 是猕猴衰老；不是可默认比较的TLE记忆研究。
- 即使出现正确疾病词，也可能只是背景/排除条件。另两组仍需核实实际研究人群、暴露、测量和对照，不能只匹配关键词。
- 按job_id取满可以复现技术样本，却不能保证共享命题密度。work_key不同也不证明受试队列独立。

这证明**我们构造样本有问题**，不是证明原始CORPUS损坏，也不是证明所有单论文命题都应合并。

### 2.2 实验B的“0/12”和“18多论文组”无效

- 历史B评分把召回键中的 `PAPER:...` job_id 与参考中的 `PMID:...` work_key直接比较，ID空间不同。评分脚本 `_expB.py` 已在上轮清理，其实现依据当时执行记录复核；目前保留的报告只保存结果，不能单独重现评分实现。这本身也是审计留存缺口。
- 所谓12个正例混合strict/hierarchy，**9个是同论文对**；跨论文召回本来就排除同论文。
- 面板中的**跨论文严格等价正例为0**。严格跨论文召回的正确解释是 **N/A**，不是0，也不是召回下界。
- 原full120账本的317个浅层端点组中，18组有多条观察；按 `len(set(work_key)) >= 2` 重算，**多论文组是0**。这些浅层键还没有包含完整scope/result，不应当作科学等价分组。
- full120标签实际只包含剩余108篇，另12篇在smoke12。当前加载器分别接受67和7篇，合计 **74篇/385观察**，不是67/120。

### 2.3 “98篇ready”不是正式接受状态

`rescore_run_v2.py`在一个论文多个HTTP200响应中事后选最好状态；没有按加载器的完整要求检查finish_reason，fragment_errors仅记录而不决定状态，也没有正式不可变升格收据。它回答的是另一问题，不能直接替代发送时账本。

因此，**67与98的差距不能直接归为加载器bug**。未来应按固定版本校验器、完成状态、响应/输入哈希、选择政策及失败记录逐条重审，另外记录promotion，不能挑最好响应后声称单次运行成功。

### 2.4 实验A不是科学准确率

旧匹配用半引文命中/0.25 Jaccard；一个长句可以包含多个不同研究结果。匹配时使用方向一致性，再计算方向一致率，会引入循环偏倚。相关系数的positive/negative也不能统一转换为组间higher/lower。

旧root参考存在复合单元、scope推断、显著性/方向标注和来源对应问题，且不是本批API之前的盲冻结参考。因此不再将 **129/132、90.4%方向一致**作为抽取科学绩效。逐字引文命中只验证文本出处，不证明该文本支持抽取结论。

### 2.5 实验C不能排除模型问题

旧面板只有一个标为strict的同论文对，没有跨论文strict正例。部分层级标签本身不成立：aMCI和AD并非严格包含；纵向变化和SPMS/RRMS组差并非同一比较；gamma预测记忆和与fMRI区域一致不能自动等价。真实模型侧还依赖A的未科学确认匹配。

84/86硬拦描述了流水线行为，**不证明84个都该放行，也不证明模型有能力识别共享命题**。总共8次模型裁决不足以隔离这些因素。需要分别测试参考、抽取、召回、门控、模型，而不是合看最终多论文率。
