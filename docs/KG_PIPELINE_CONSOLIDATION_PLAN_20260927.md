### 问题2的链条定义与最小实现范围（用户补充，2026-09-29）

用户明确：“我们的 hypothesis 同样是图谱中的一个链条”，“每个 topic 对应一种或多种类型的链条”，“类型 a 的 node -> 关系 a -> 类型 b 的 node -> 关系 b”，“链条抽取之后还需后处理一下，单纯的链条可能过于简化了关系”。据此，生成单位固定为**类型化链条及其证据解释**。

1. **topic → 一种或多种链条模板。** 复用已有节点类型与TaskChain，在每个相邻节点位置补充允许的关系类型、方向；模板选择与图谱记录绑定。链条长度、节点位置、关系与方向都有明确约束。
2. **只读枚举 → 合规链条。** 复用现有路径生成能力，从当前图谱中找符合模板且与topic相关的链条，逐步验证真实节点/边、端点连续性、类型、关系和方向。只交付全部通过的链条，无法匹配可以为空；“100%”指输出对已声明格式的合规性，不是召回率或科学正确率。已有网页无向路径枚举不能直接充当这一保证。
3. **证据后处理 → 可检验hypothesis。** 把问题1返回的论文、evidence、metadata绑定到每条边，保留人群、条件、测量、时间、方向、否定及来源核查状态。检查相邻证据的适用范围，说明关系中的限制、调节/交互等已有信息；缺失保持未知，不把跨条件的边机械串成机制。保留机器可读链条，另外形成假设表述、依据、明确预测及限制，标明哪些是已有观察、哪些是整链新增推断。后处理不能靠措辞把相关关系改成因果；结构若需改变，必须重新从图谱匹配和校验。

交付仍是一个候选列表，每条保留 `chain/template + 逐边证据与条件 + hypothesis/prediction/limitations`，直接供问题3在同一候选池上打分和ranking。图谱不修改，不在本步做GNN、创新性排序或三agent评分。

### A. 最终目标与完成标准

**输入一个研究问题，idea 模式能够利用可追溯证据，提出有科学依据、有明确研究增量、可检验的候选假设，并如实区分已知结论、潜在创新和证据不足。**

验收对象是实际 idea 入口的交付，不是图谱规模、共享命题率、字段数、测试数或 GNN 分数。有效意味着：

- 用户选择的 idea 模式与 `novelty_first` / `balanced` 策略确实进入运行链路，失败可解释、请求可追溯。
- 引用确实支持对应论点；已知结论不包装为创新，查不到文献不等于首次发现。
- 每个保留候选说明人群/对象、预测或干预、结局、对照与可证伪结果；数据或实验条件不可得时明确限制。
- 在固定问题、资源上限和统一评审口径下，相比现有版本提高可用候选质量/交付率，或在质量不下降时减少耗时与成本；不能通过放宽门控来换取更多输出。
- 证据不足时允许零候选并交付具体缺口；但“每次都拒绝”不算模式有效。分别报告候选交付和正确弃权，不能互相充数。

### B. 范围与最小链路

`研究问题 → 有界检索与原文核对 → 候选假设 → 科学性/已有工作/可检验性审查 → 排序与选择 → 证据及检验方案交付`

KG 用于检索、组织证据与提供结构信号；GNN 用于待验证的辅助排序。**不要求先完成全库重抽、全图合并或证明跨论文严格等价，才能开发和验证 idea。** 严格等价正例为零，只说明当前面板不能估计严格合并召回，不证明整个图谱无效，更不是 idea 的停工条件。

来源仍须可信，但可先使用少量逐项核对的论文证据，不依赖未经验证的共享命题或图边。若确需跨论文合并，则该能力单独通过验证才能使用；不放松科学定义。

保留 `novelty_first` 的证据门控和 `balanced` 的综合选择定位。先核实真实接线与缺失分数行为，再决定最小修改；不自行调整现有权重。未测量与低分必须区分，不能把占位零分宣传成实测 GNN 或完整综合评分。

### D. 小型验收设计与停止规则

- **建议规模：6 个开发问题 + 6 个冻结验收问题**，每题最多交付 3 个候选。先覆盖真实使用场景、已知先例陷阱、证据不足和可操作性边界；问题级隔离，并检查来源/队列/既有曝光。只是拟定范围，清单和具体预算冻结前不运行。
- 开发与验收均检查两个选择策略；能复用同一批已审查候选进行离线策略选择时不重复生成/评审。策略差异不等于模型质量差异。
- 评审量表在看本批模型输出前固定：来源支持、与已有工作的具体差异、科学合理性、可检验性各自判定；不把模型投票当独立验证。不要求先写出唯一“正确 idea”，也不把预写答案提供给生成器。
- 端到端比较使用相同问题、可用资料边界与资源上限；GNN 排序对照固定候选池和证据。逐项对照，避免把搜索预算差异误算为算法增益。
- 关键错误（虚构/不支持的引用、把明确先例当创新、跨人群/测量移用结论）必须在开发阶段处置；若验收仍出现，不宣布该范围可无人值守。报告分子/分母与具体错误，不从 6 题推出全领域准确率。
- 候选可用性和证据缺口分别计分；实质新颖性只在已说明的检索范围内评判，不许声称已经证明首次发现。只有技术通过、只有零误合并或只有零输出，都不满足最终目标。
- 开发最多进行一轮针对已定位根因的修正再复测；仍不足则总结限制并缩小使用范围或停止，不不断增加 schema、样本、模型或预算。新验收轮需要新的未暴露问题和明确范围。

## 1. 目标与原则

目标：把同一概念的多个并存实现收敛为**唯一负责人**，使新增能力只能进入既有位置，而不是再开新模块。收敛不降低科学标准，不改写旧产物。

原则：

- **五个唯一负责人**：来源包、候选结构、规则、传输与账本、评估。
- **流水线一个版本号**，模块不再各自 v1/v2/v3。
- **旧产物只读**：不改写、不静默升格、不重新解释既有账本。
- **行为等价优先**：改动前先在冻结产物上证明逐项等价；任何行为差异必须单独记录并请用户确认。
- **每步一个反例测试**；测试通过不等于科学验收。
- 本轮及后续步骤均不涉及：API 调用、子代理、后台任务、重抽取、删除证据、生产/固定层/CORPUS/heldout/E: 写入。
