# GNN 辅助排序：收敛实施计划

本文件是本任务后续实施的统一入口。2026-09-27 用户批准整体方案，并要求每步完成后回顾计划。
旧实验与撤回记录保持不变；本计划不授权新的训练预算、API、生产接入或受保护数据读取。

## 固定目标与边界

只检验：在来源隔离、条件一致的候选组中，一个 GNN 是否比一个简单结构基线更有助于找回来源支持的关系。
GNN 分数不是科学真实性、创新性或概率。此次不建设路径模型、自动消歧、模型搜索、调度系统或 KGE 对照。
固定层、生产路由、40 篇保护集、历史结果和原始语料不变。旧通用训练器不是本任务入口。

## 三阶段与回顾

1. **统一契约**：来源证据 → 审阅后的冻结数据包；定义候选组、隔离和排序指标。不得以自动匹配代替语义审阅。
2. **唯一入口**：检查 → 持久预算预留 → 受监督训练 → 验证选模 → 一次最终测试 → 报告。复用已有保护模块，不新增框架。
3. **授权后对照**：只有新的数据审阅与具体预算授权均完成，才执行一个固定 GNN 配置与结构基线。无增益不自动加跑。

每一步完成后记录：完成内容、验证结果、是否偏离目标、下一步及停止条件。
代码准备与真实科学数据准备分别记账，不能把合成测试数据当实验数据。

## 数据包契约

一个 JSON 数据包包含 `schema_version=1`、`task=source_supported_ranking`、`items`、`sources`、
`assignments`、`edges`、`protected_works`、`exposed_works`、`review`。完整规范由唯一入口的检查函数执行。

- `items` 复用 `validation.check_item`：实体 ID、有向关系、测量、scope、证据角色、来源/家族、原始文本哈希和引文偏移、审阅理由。
- 每项新增 `query_id`；同组必须具有相同 source/relation/measurement/scope/role，不同 target，至少两个候选和一个 supported；全组同 fold。
- supported/contradicted/unresolved 是审阅结论。unresolved 不算科学负例；contradicted 可缺失，不能靠反转或缺边补齐。
- `assignments` 在预测前冻结，必须满足来源/家族/事实/端点代理隔离，候选组也不能跨 fold。不得为填满测试集改变隔离原则。
- `edges` 只接收来源绑定、审阅为 supported 的图边，复用现有泄漏检查。当前最小版本不支持外部节点特征，使用训练图 ID 的可学习嵌入。
- 固定参考层保持原样；尚不能满足该边契约的固定边不会自动进入实验图。这是小型合格子图实验，不代表整个 KG。
- `review` 必须明确 reviewer、reference 冻结时间、预测前冻结声明及 exclusion 清单审阅。声明本身不证明审阅正确，仍需主助手核验。
- 保护/曝光清单由来源审阅流程提供；哈希和非空检查不能证明它们完整。不得读取 protected 原文来补齐实验。
- 图外实体/关系不打分，也不加入随机测试实体嵌入；报告覆盖率。验证/测试各至少有一个完整可测候选组。

## 固定比较与指标

结构基线为训练图无向共同邻居数，不看来源标签、测试边或额外图；方向性 GNN 为两层 R-GCN，64 维、dropout 0.1、AdamW lr 0.001、最多 50 epoch、patience 5、seed 123。
不搜索参数。训练仅重建合格训练边，每个正例一个随机替换端点对比样本；这些样本不是科学反例，且只对训练边做排重，不用测试标签引导采样。

主指标：同一完整可测候选组中，已知 supported 候选的平均倒数排名，再对组取平均；并列用平均排名。
这是 **known-support MRR**，不是全标注 MRR 或科学准确率。未标注/未决候选排在前面不意味着它们错误。
同时报告组/项覆盖率、不完整组、标签分布和已知支持 top-1 命中；不完整组不挤进主指标但必须保留在覆盖率分母。
基线与 GNN 使用同一可测集合。仅 validation MRR 选择 checkpoint，冻结后一次 test；报告逐项分数而非仅汇总。
没有可信反例，不计算真假准确率；本最小流程不学习弃权阈值，缺映射的不可测不冒充语义弃权。
最终正向差值也只是一次有限对照结果，不自动获得显著性、独立验证或上线资格。

## 预算与执行边界

旧预算剩余为 0。新授权必须绑定整个数据包、执行代码及一个固定账本；换输出目录不是预算重置。
数据检查命令不预留预算、不调用优化器、不访问原始数据库。只有显式 run 使用新授权。
工作进程在分配模型前安装 CUDA allocator 上限，父进程监测时间/RSS；不保证第三方或其他进程 GPU 占用上限。
失败/未知尝试进入 HOLD，不自动恢复或重试。固定图与生产均只读，所有结果写到新的输出目录。
